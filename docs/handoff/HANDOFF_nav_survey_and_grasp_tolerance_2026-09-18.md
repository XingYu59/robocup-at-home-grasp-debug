## 1. 问题①：根因（3 条，各自独立、都有数值证据）

餐桌 3 的脚印 = map x∈[2.10, 3.30]、y∈[1.75, 2.25]（`example.world`: pose 2.7 2 0 0 0 1.57，
桌面盒 0.5×1.2 ⇒ 世界系 x±0.6 / y±0.25）。**南边是餐桌 2、西边是餐桌 1（相邻紧贴）**
⇒ 真正站得下人的只有**北**和**东**两面。

### 根因 1：近看位按"离桌心"算 ⇒ 东西向只剩 0.08 m（旧代码）
旧 `CLOSE_LOOK_DIST = 0.68` 是"到**桌心**"的距离。实测（`check_dining_view_geometry.py`）：

| 方向 | 近看位 | 离桌沿 | Nav2 `free(0.28)` |
|---|---|---|---|
| 北 | (2.70, 2.68) | 0.430 m | ✓ |
| **东** | (3.38, 2.00) | **0.080 m** | **✗ 不可达** |
| 南 | (2.70, 1.32) | 0.430 m | ✗（压在餐桌 2 上）|
| **西** | (2.02, 2.00) | **0.080 m** | **✗ 不可达** |

⇒ 从东/西侧看时，"近看位"这个**导航目标点**直接落进桌子脚印里。

### 根因 2：站位余量 0.26 m < Nav2 的 robot_radius 0.28 m（旧代码）
`param/turtlebot3.yaml: robot_radius: 0.28`、`inflation_radius: 0.45`。
代价地图里距障碍 < robot_radius 的栅格是 `INSCRIBED_INFLATED_OBSTACLE(253)`，
而 DWB 的 `BaseObstacleCritic` 把 253 判为**非法轨迹**
⇒ **所有**站位（= 桌沿外 0.26 m）都到不了：控制器失败 → 重试 → 车头一直朝桌子顶 → 撞桌子 ✗
实测：`(2.70, 2.51)` 的 `free(0.28) = False`；改 0.34 m 后 `free(0.28) = True` ✓

### 根因 3：支撑面门被关掉 ⇒ 目标选择被"邻桌幻影"劫持（L1~L5）
`SUPPORT_GATE_ENFORCE=False` 时 `_on_support` 直接 `return True` ⇒ 邻桌物体也被当成本桌目标：
2026-09-18 日志：观察位 (2.70,3.15) 拍到**餐桌 2** 上的物体（gelatin_box 被闭集复核误标成
`potted_meat_can` @ map(2.951,1.569)，该点**确实落在餐桌 2 脚印内**）→ 被选为目标
→ 站位解算成 **(3.561, 1.569, yaw=π)**（餐桌东侧）= 用户看到的"导航到餐桌另一边"，
且该点距地图障碍 0.261 m < 0.28 ⇒ 又是非法目标点 ⇒ 顶桌子 ✗

## 5. 问题②：视觉侧改了什么（`turtlebot3_manipulation_grasp/scripts/detect_grasp_target_node.py`）

审计结论（按量级，证据见 §7）：**跨调用 4~20 cm 的抖动，主因是"类别↔实例错配"** ——
同一个物理罐两次调用先被标 `master_chef_can`、后被标 `gelatin_box`，
而投票只在"该类别"的框里取中位数 ⇒ **标签一换，位置就换到别的物体上** ✗

| # | 改动 | 为什么 |
|---|---|---|
| 8 | **订阅与服务分到不同回调组** | rclpy 里同一节点默认只有一个 `MutuallyExclusiveCallbackGroup` ⇒ 服务回调（20~60 s）跑着时**相机/深度/TF 回调全被挡住** ⇒ 缓存冻结、等不到新帧、多帧投票等于反复跑同一张图 ✗。现在订阅 = `ReentrantCallbackGroup`、服务 = 独立组 ⇒ 多线程 executor 其它线程能继续收图 ✓ |
| 9 | **尺寸核对按距离放宽 + 只降权不丢帧** | 实测真目标 `tomato_soup_can` 在 1.22 m 处只有 ~29 px，SAM2 掩码只盖 40% 宽 ⇒ 实测横向 0.027 m < 固定下限 0.7×0.066 = 0.046 m ⇒ **5 帧全被丢弃** ⇒ 只剩邻桌幻影 ⇒ 目标被劫持 ✗。现在下限 0.7×narrow（≤0.6 m）线性放宽到 0.35×narrow（≥1.0 m）；仍不过就**置信度 ×0.7 保留候选**（输出置信度也用它）✓ |
| 10 | ⚠ **副作用与配套** | 远处掩码只盖一侧 ⇒ 横向中心可能偏 ~10 mm ⇒ 由 §6 的**侧向偏置重抓**吸收 ✓ |

**未改动、需要团队决策的项（都在 §7 给了证据与风险）**：
`contract_range_offset = −0.022`（手工前移偏置，与 `contract_axis_pct=5` 叠加成 ~35~42 mm 的
系统性"朝相机拉近"，而 `sweep_offset` 实验在径向 ±40 mm 内**没有出现接触**，
与该偏置的假设矛盾 ⚠）；`close_hand_squeeze = 0.0015`（判别余量只剩 3 mm，见 §6 注）；
长方体后退量在掩码路径上不按偏航修正（`min(d,w)/2`，45° 时应为 44.9 mm）；
相机俯仰 0°（高出桌面仅 39 mm ⇒ 平面约束病态，3.7 mm/px）。

## 6. 问题②：抓取容错（`grasp_phase.py`）

| # | 改动 | 关键点 |
|---|---|---|
| 11 | **成功判据换成"夹到没有"** | 新纯函数 `classify_closure(指令间距, 实测最小间距, 窄边)` → `contact` / `empty` / `unknown`。判据是**实测 − 指令**（与 squeeze 取值无关）：空合 ⇒ 差≈0；夹到 ⇒ 手指被挡住，差 ≈ 2×squeeze ✓ |
| 12 | **不再信 `stage=0`** | `call_grasp` 现在返回 `(success, stage, msg, closure)`；`run()` 里 `stage=0 但空合` ⇒ **判失败并换目标**（服务报成功只是 MTC 的逻辑 attach，见 `pick_and_place.cpp`）✗→✓ |
| 13 | **偏置重抓阶梯** | `GRASP_RETRY_OFFSETS`（base 系：x=朝物体、y=侧向=两指合拢方向）+ `MAX_GRASP_TRIES=4`：`(0,0)` → `(0,±12)` → `(0,±24)` → `(−20,0)` → `(−40,0)`（截断到 4 档）。偏置加在**发给服务的抓取点上**（障碍物一起平移）⇒ 不用动车、不用重新导航 ✓ |
| 14 | **阶梯顺序的证据** | 2026-09-16 `sweep_offset` 沿**径向**扫 ±40 mm、9 档**全部空合** ⇒ 那次主因不是径向偏远，而是**侧向偏差**：罐直径 66、开口 80 ⇒ 侧向只有 **±7 mm** 余量（糖盒 ±21 mm），侧向一偏两指就从旁边滑过，**任何径向偏置都救不回来** ✗ ⇒ 先侧向后径向 ✓ |

**代价与预算**：每次重抓 = 一个完整 MTC 周期（规划+执行，约 30~60 s）⇒ 最坏 4 档 ≈ +2~4 min。
比赛限时紧就把 `MAX_GRASP_TRIES` 调到 2（只试"原估计 + 一个侧向档"）✓

**判别力提醒**：`close_hand_squeeze=0.0015` 时"空合(窄边−3) vs 夹到(≈窄边)"只差 3 mm，
和默认阈值 `CONTACT_TOL_MM=2.5` 贴得很近 ⇒ 想要更稳的判别力把它调到 **≥0.004**（两档差 ≥8 mm），
代价是每指多挤 3 mm（现场记录 0.0070 会把薄盒挤跑 ⚠）——这一条建议 A/B 一次再定 ✓

## 7. 审计结论（视觉/抓取两侧的误差来源，供后续排期）

按量级排序（证据：`~/.ros/log/` 现场日志 + `HANDOFF_harness/.run/` 实验记录）：

1. **类别↔实例错配（100~1000 mm）** —— 同一物理罐两次调用报 `master_chef_can` / `gelatin_box`；
   同类 `gelatin_box` 两次报 (1.063,−0.028) 与 (0.667,+0.096)（差 0.4 m）。
   ⇒ 已被 §6 的"接触闭环 + 空合换目标"兜住（抓不到就换，而不是拿着错点硬抓）；
   根治方向：`_fresh_target` 里要求"类别稳定 + 位置与跟踪点一致"（现在只有 0.35 m 的半径门槛）。
2. **手工前移偏置栈 ≈35~42 mm** —— `contract_axis_pct=5`（比中位数前移 13~20 mm）+ `contract_range_offset=−0.022`。
   两者都由二分试出；但 `sweep_offset_20260916_213228.log` 在径向 ±40 mm 内**无一档接触** ⇒ 与"偏深"假设矛盾 ⚠
   ⇒ 建议：**先把 `contract_range_offset` 设 0**（`ros2 param set` 或命令行 `-p contract_range_offset:=0.0`），
   让 §6 的偏置阶梯实测真值，再一次标定；不要"视觉侧 + 驱动侧"双重补偿 ✗
3. **掩码边界抖动被放大** —— 1.2 m 处掩码只盖 41% 宽，而轴向用 5% 分位（几十像素 ⇒ 1~2 px 决定统计量）
   ⇒ 重复性差。根治方向：加"掩码覆盖率 ≥0.7 才采用，否则对框 ROI 上采样重跑 SAM2" ✓
4. **长方体后退量在掩码路径不按偏航修正**（`min(d,w)/2`，45° 时误差 ~26 mm）。
5. **`_ground_point`（地面约束测距）实际是死代码**：相机只高出桌面 39 mm < 80 mm 门槛 ⇒ `ok=False` ⇒ `auto` 永远回退掩码法。
6. ~~⚠ mimic 的证据链要更正~~ ⇒ **已作废（用户 2026-09-18：mimic 已验证过 ✓）**，
   见 §9.7。`两指真实间距` 继续当"夹到没有"的判据用 ✓
   （原始疑虑保留在此仅供追溯：曾怀疑 Fortress 无物理 mimic ⇒ TF 间距不足以证明两指都在动）
7. `grasp_lift: 0.000` 被 `pick_and_place.cpp` 当成"未配置"重算 ⇒ `gelatin_box` 得到 **−0.009 m**
   （指尖比桌面低 4.5 mm）⇒ 必然 NO_SOLUTION；`close_hand_squeeze` 三处兜底值不一致
   （YAML 0.0015 / C++ 0.002 / 驱动 0.0045）；`reach_max` 三源（0.85 / 0.75 / 0.75）。

### 10.10 ★★ 跟随位移：用"被推走"当方向传感器（2026-09-19，夹爪修好之后的下一步）

```
重测[3]: base(+0.359,-0.014)  被推走 10 mm
重测[4]: base(+0.375,-0.023)  被推走 18 mm      ← 一直往"更深 + −y"走
```

**可用信息在哪**：视觉的**绝对**位姿有系统偏差 ✗，但物体**位移**是**差分**量 ——

**物理推导**：手指只会把物体推向**它自己所在的那一侧**（手指从轴线往外推）⇒
**观察到的位移方向 = 物体真实位置相对视觉估计的方向** ✓

**实现**（`grasp_phase.py: _grasp_with_offsets`）：
```
修正偏置 bias += 2 × (本次观测到的位移)        # 学到"视觉估计要往哪边修"
下一档抓取点 = 当前视觉估计 + bias             # creep / 重测 / 重新对正都不丢 ✓
进入"跟随模式"后不再叠固定阶梯的小偏置          # 免得把已经瞄对的点又推歪 ✗
```
⚠ 第一版写错过一次：把跟随点当"绝对点"存 ⇒ 紧跟其后的 re-creep 用视觉估计重建基准，
把学到的修正**冲掉了** ✗ ⇒ 现在改成**相对偏置**，已在单测里锁住 ✓

**它同时就是"测量视觉系统偏差"的手段**：日志里会打
`修正偏置更新为 (a, b) mm`；连续几次收敛到同一个 (a, b) ⇒ 那就是视觉的系统偏差 ✓
测到之后可以**一次性补偿**（新加的视觉侧参数，2026-09-19）：
```bash

     # 或直接给节点参数：
     -p contract_lateral_offset:=<相机系横向分量，m>     # 默认 0.0 = 不补偿
```
> 为什么需要这个参数：现有自检（桌平面校验 / 尺寸法 vs 深度法 / 掩码法 vs 框心法）
> 对"相机→base 的**横向平移**"**全都免疫** ✗，而残留误差正好是这个量级（1~3 cm）✓

**下次跑要看的三行**：
1. `重测[N] … 被推走 XX mm（Δx=…, Δy=…）⇒ 修正偏置更新为 (a, b) mm` ← 偏差方向/幅度
2. `重抓[N/5]：视觉估计 … + 修正偏置 (a, b) mm + 阶梯 …` ← 是否在朝一个方向收敛
