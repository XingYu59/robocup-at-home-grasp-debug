## 2. 已经"实测确认"的事实（可复现）

1. **手部几何硬约束**（由 URDF 真实碰撞体量出，`check_grasp_geometry.py` 可复现）：
   - 掌面（fr3_hand 网格）在**指尖平面上方 37.4 mm**（槽外区域 |y|>40 mm）
   - 指腹（橡胶指尖，唯一真正夹住物体的面）在**指尖平面上方 9.0 mm ~ 下方 9.5 mm**
   - 两指之间那条"槽"的净空是**随物体脚印宽度变化的**（实测：coke can 半宽 34 mm → 物体顶面只能升到 +92 mm；sugar_box 半宽 19 mm → +140 mm）
   ⇒ 抓取高度必须按**精确碰撞扫描**取"可行角 ≥8 的最低高度"，不能按"高度的 1/4"拍脑袋 ✗
2. **机械臂执行精度没问题** ✓：指令 `base(0.356, 0, 0.78)` → 实测指尖轨迹 `x 0.214→0.358` ✓（差 2 mm）。**任何"臂没到位"的说法都是仪器/误读**（见下条）。
3. **仪器曾经骗过我（务必知道）**：初版"指尖最低点"只保留 z 更小的采样，而 **home 位姿的指尖 z(0.914) 比抓取位姿(0.9195) 还低** ⇒ 永远记录 home 值 ⇒ 我据此误判"机械臂差 18 cm 没到位" ✗。现改为记录**整个调用期间的 x/z 范围** ✓。
4. **两指对称合拢正常** ✓（真实间距 = 2×关节值 ✓，mimic 在 Fortress 里**没坏**；我最初那行"mimic 失效"的判据公式写错了 ✗ 已修）。
5. **相机本身正常** ✓：用机械臂自身标定（把指尖放到已知位姿看它在画面里的位置）差 7 px (≈1 cm) ✓；发布内参 fx=530.47/cx=320 与仿真 hfov 反算的 530.2 一致 ✓；画面延迟 0.01 s ✓。
6. **手指可视网格 vs 碰撞盒一致** ✓（差 0.6 mm）—— 所以"看到手指在哪"就是"物理在哪" ✓。
7. **`sugar_box` 模型有一处真实不一致** ⚠️：SDF 碰撞盒 **0.038 × 0.089 × 0.175 m** ✓，但可视网格 `textured.dae` 顶点包围盒 = **0.0495 × 0.0941 × 0.1761 m** ✗（夹持轴上胖 **11.5 mm**，约 30%）⇒ **"看着包住了" 不等于 "物理上夹住了"** ✓（这条值得跟裁判讨论 ⚠️）。**但它解释不了"合到 29 mm 毫无阻挡"** ✗（物理盒 38 或 49.5 mm 都会卡住手指）。
8. **视觉是当前最大的短板** ✗（实测数字）：
   - 同一场景、车没动，跨调用报出的位置差过 **4~20 cm** ✗（多次实测：0.395 / 0.214 / 0.335 / 0.401 …）
   - 一次调用内部各帧是一致的（离散 0 px ✓）⇒ 抖动来自**跨调用/跨 pass**，不是单帧噪声
   - 掩码法与框心法**互相一致**（差 1~15 mm）⇒ 说明偏差是**共同来源**（同一张图 + 同一套 TF），我的交叉校验查不出它 ✗
   - 小物体召回很差 ✗：新加的 `tomato_soup_can`（66×101 mm）在 1.2 m 处**完全认不出来**（`--classes "tomato_soup_can"` 直接返回空）
   - 标签会串 ✗：糖盒曾被报成 `mustard_bottle` / `tomato_soup_can` / `cracker_box` / `chips_can` / `apple` 等

## 3. 未解问题与方向（按可能性排序）

### ★ 问题 1（最可能）：喂给机械臂的**抓取点系统性偏"远"**
**证据链**：
- 用户在多角度观察：夹爪**确实包住**了物体 ✓，但物体**一点不动** ✗
- 手指自由合到 29 mm（= 指令值 ✓、无阻挡 ✓）⇒ 合爪时两指之间没有实体
- 几何反推：要让 38 mm 厚的盒子**全程不被碰到**，偏差必须是——**横向 ≥7.5 cm**、或**指尖整体高于盒顶（≥5 cm）**、或**前后 ≥5.6 cm** ✗ ⇒ **"一点点偏差"物理上做不到"完全不动"** ⇒ 偏差量级是 **5~8 cm**
- 相机画面里：糖盒**顶部被画面顶边切掉**（⇒ 真实距离 < 0.34 m ✗），而系统报 0.35~0.40 m ✗ ⇒ **距离估计偏大 ~6 cm** ⇒ 手指落在物体**后面** ⇒ 用户看到的"机械臂位置太远" ✓
**下一步（只改这一处）**：把视觉"距离/位置"估计的每一步打出来定位抖动来源——
① 框心像素深度 ② 掩码点云深度分布（10/50/90 分位）③ 契约点的"后退窄边/2"校正量 ④ 相机→底盘 TF 的平移分量；
**判据**：让机器人**停住不动**，连续调用视觉 5 次，若 (x,y,z) 抖动 > 1 cm ⇒ 就是它。

### 问题 2：薄高物体的"顶抓"本身不稳
`sugar_box`(38×89×175 mm) 只有 2~14 个可行采样角；夹持点被迫在顶面下 52 mm（离重心 52 mm），
抗倾覆力臂只有半个厚度 19 mm ⇒ 夹持力稍大就会推开物体 ✗。
**方向**：`grasp_params.yaml` 里记录过"**水平侧抓**"配置（`[0,0,0.005,0,-π/2,0]`），当年被 MTC 的 ComputeIK 全拒（25/25 无解，怀疑与 tip 传参/LMA 求解器有关）——修好工具链后，细高物体的正解是侧抓 ✓

### 问题 3：视觉召回/词表覆盖不了小物体
见 §2.8：`tomato_soup_can` 在 1.2 m 处不存在于检测结果里 ✗
**方向**：观察位再近一点（近看位 0.68 m 已自动启用 ✓）／对目标类别做**闭集 patch 分类**（而不是依赖开集 phrase）／必要时对"四个比赛类别"单独做小目标召回

### 问题 4：`sugar_box` 可视/碰撞不一致（模型问题，非算法）
见 §2.7。**建议交给裁判/模型所有者**：把可视网格与碰撞体对齐（或反过来）✓


```
[3] 场景: 目标 "sugar_box" (h 0.1750 d 0.0380 w 0.0890) @ (x, y, z)   ← 箱心位置
[3] 抓取高度: "sugar_box" h=0.175 → lift=0.0520（可行窗口 [0.0501, 0.0785] ✓）
[3] 箱=(h …) lift=… 箱体偏航(规划帧)=±9x°                             ← 必须是 ±90° 左右，不能是 0
[3] 合爪目标: 物体 0.0380 m … − 干涉 0.0045 → 关节 0.0145
[3] 解轨迹… ↑ 抓取采样角 1.5708 rad = 90.0°（90/270 = 正对薄边）
[4] 抓取点重测: sugar_box base(+0.3xx,+0.00x) conf=…                  ← 这一帧就是最终抓取点
[4] 指尖轨迹(本次调用): x 0.214→0.3xx（最远 x 应≈抓取点的 x ✓）
[4] 合爪实测: 关节 起始 0.0400 → 最终 0.0145（两指间距 29.0 mm）
[4] 两指真实间距: 起始 80.0 mm → 最小 2x.x mm     ← ★ 关键判据，见下
```

**★ 只用这一行就能判"有没有夹到东西"**：
- 最小间隙 **≈ 物体窄边**（如 38 mm / 66 mm）⇒ **手指被物体挡住 = 夹到了** ✓
- 最小间隙 **= 指令值**（如 29 mm）⇒ **两指之间是空的** ✗（此时问题一定在"抓取点的位置/高度"上，而不是别处）

## 6. 踩过的坑（避免重踩）

1. **别只看"stage=0 / success=true"**：MTC 的 `attach object` 只是**规划场景里的逻辑附着**，物体没夹住也照样报成功 ✗
2. **`GripperActionController` 默认 `goal_tolerance`**：命令 0.0（全闭）会因位置误差过大而 abort；命令"比物体窄一点"才是对的 ✓
3. **合相干涉不是越大越好**：固定 7 mm/指 对 38 mm 薄盒 = 37% ✗，实测会把物体挤走；但太小又夹不住 ⇒ 现在是一个参数、现场试
4. **别用"z 最小"的采样记录指尖位置**（home 位姿更低 ✗，会误判"臂没到位"）
5. **视觉一次调用 60~90 s**（3 帧投票 + 闭集复核 + 窄词表复核）⇒ 调用方超时必须 ≥150 s，否则会**静默退回远距离旧估计** ✗
6. **多帧投票不要选"分数最高的那帧"**（那是误检的那帧的概率很高 ✗）
7. **目标时间戳必须重打**：适配层一条消息带的是**拍照时刻**的 stamp，直接透传会被抓取侧判"不新鲜"拒收 ✗
8. **沙箱里 cv2.imwrite 失败只警告不报错** ⇒ 写图后一定要检查返回值
9. **换桌子/物体**：改 `grasp_params.yaml` 的 `support_surface.pose` 一处即可 ✓（orchestration 侧现在读同一个文件 ✓）；但 `NEIGHBOR_TABLES`（并排餐桌排除）只在餐厅那三张桌子时启用 ✓
10. **世界复位**：重启 Gazebo 即可把被动过的物体放回原位 ✓（物体是 `<include>` ✓）；一旦盒子被碰倒，后面的抓取**必然失败**（按"立着"算的高度会夹在它上方的空气里 ✗）——重跑前先看一眼盒子立着 ✓

### 9.1 症状与推理（都不依赖 gz 真值）
糖盒、番茄罐两只、两种形状，都是同一个签名：

| 证据 | 数值 |

| 合爪实测间距 | 糖盒 29.0 mm（= 指令值）· 番茄罐 57.0 mm（= 指令值）⇒ 两指之间根本没有物体 |

| 两条独立估计（掩码法 / 框心法）之差 | 只有 1~15 mm ⇒ 是**共同偏置**，不是随机噪声 |
| 已逐项验证为正确的环节 | 臂执行 ±4 mm · 相机外参（自标定 ≤1 cm）· 内参 · 深度编码 · 深度尺度（桌面 z≈0.780）· 手指网格 vs 碰撞箱（0.6 mm）· 高度链 |

⇒ 误差集中在 **掩码↔深度** 这一段：掩码里混进的桌面/背景都比物体**远**，

### 9.2 补丁（全部在 `turtlebot3_manipulation_grasp/scripts/detect_grasp_target_node.py`，可单独关掉做 A/B）

1. **地面约束测距 `position_source=plane`**（默认 `auto`）
   掩码底边像素落在桌面上（z = `support_z` 已知）⇒ 由内参 + 相机外参反解该像素深度
   `Z = (support_z − t_z) / (R[2,:]·((u−cx)/fx, (v−cy)/fy, 1))`，再反投影出底边**前缘**，
   沿水平视线后退"可见面→轴心"的距离即轴心 ✓ **完全不看深度图** ⇒ 与深度链路独立，
   天然躲开掩码吃背景的问题。视角太平（相机高出桌面 <8 cm）或底边跨度超过物体脚印
   对角线 +5 cm 时自动不采用并回退。
2. **后退量改成几何精确值**（`yaw_backoff`）：圆截面后退 r；长方体退支撑函数
   `(d/2)|cosφ| + (w/2)|sinφ|`（φ = 视线与物体 x 轴夹角，来自 `object_yaw_map` 与 map→base 的 TF）。
   原来固定用 `min(d,w)/2`，斜看薄边时少退 2 cm 以上 ✗（离线自测：正对宽边 44.5 mm 精确 ✓）
3. **距离闸门 + 掩码腐蚀**（`mask_erode_px`）：只保留"物体自己那一簇"深度
   `[20% 分位, 20% 分位 + 物体最大尺寸 + 3 cm]`，并回报剔除比例 ——
   剔得多就是"掩码在吃背景"的直接证据 ✓
4. **桌平面校验**（`table_check`，每次视觉调用一条）：网格取样深度，用平面约束挑出桌面像素，
   反投影 z 应恒为 `support_z`。**一次同时验证深度尺度/编码 ✓ 内参 ✓ 相机外参 ✓ 支撑面高度 ✓**
   （z 随像素行线性变化 ⇒ 俯仰/内参问题；只是整体偏移 ⇒ 高度问题）

### 9.4 仿真里怎么判读（下次跑的日志）
- `桌平面校验: N 个桌面像素 → 反投影 z=… 差 … mm；斜率 … mm/px`
  **一致 ⇒ 深度/外参/桌面高度这条链没问题**，位置偏差只能出在掩码↔像素这一段；
  不一致 ⇒ 先修这条链，别急着动夹爪。
- `距离闸门[…]: 剔除 X% 远处像素` —— X 明显 >2% 就是掩码吃背景的实证 ✓
- `地面测距[…]: 轴心 base(…) 前缘 … 后退 … 底边跨度 … 影宽 … → 与掩码法差 … mm`
  · **两法差得大** ⇒ 正好说明其中一条（多半是掩码法）不可信，采用哪条看下一行；
  · `影宽` 是掩码底边的实测宽度，应接近类别尺寸（罐 66 mm / 糖盒 38~89 mm），
    差得远说明掩码框错了物体 ✗
- `→ 采用【地面测距】` / `→ 采用【掩码法】`：明确写出本次用的是哪条
